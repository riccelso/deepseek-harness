# Agent Note: 会话内查找索引投影、高亮 DOM

Status: implemented

[English](2026-10-28-conversation-find-bar.md) | 中文

## 问题

Web 客户端可以跨会话搜索，却不能在当前 transcript 内搜索。在长对话中定位早先出现的词需要滚动或浏览器自身的页面查找——它看不到收起的流程分组背后的行，也不了解会话的节点顺序。查找功能必须依据投影所知的内容来计数与排序匹配（包括收起的行），而其视觉层只能绘制已渲染的部分，并且不得改动消息内容、选区或持久 transcript。

## 决策

### 索引非 DOM 且内容完整

`find-index.ts` 为每个 Chat Node 提取一段可搜索文本（用户/插话/上下文内容，助手文本与推理，工具名/参数/结果文本，命令行，轮次错误），并按 Node 对象缓存。计数、顺序与导航来自对投影节点顺序的匹配；隐藏与收起的行仍可被搜索，因为可见性是表现层事实。流式更新只重新搜索变化部分，未变化的 Node 保留缓存提取。

### 高亮是通过 CSS Custom Highlight API 的覆盖层

绘制在会话容器的已渲染行上构建 DOM Range，注册两个高亮层（`dsh-chat-find`、`dsh-chat-find-active`）——内容、选区与 transcript 均不被改动。不支持该 API 的浏览器保留计数与导航但不绘制。图层规则位于 `ui-theme` 的全局样式表 `find-highlight.css`；文字颜色保持继承，对比度随主题 label token。

### 导航先揭示后滚动

移动到匹配项时，先点击头部展开任何包裹它的收起 disclosure（聚合工具段、流程分组），再滚动到该行——这是非虚拟化列表中对"按需反虚拟化"的收起分组等价物。

### 一个打开标志，按 Session 持久化

查找栏的打开状态是插件级单一 store，由可选的 `shortcuts` 服务驱动（`chat.find.open`：桌面端 `primary+F`，Web 端 `primary+alt+F`——未修饰组合留给浏览器页面查找，与 Settings 绑定策略一致）。词项、选项与位置按 Session 在 apply 闭包中持久化，重新打开即恢复；Escape 关闭并清除绘制。

## 影响

- 渲染文本省略索引文本时（例如截断预览），计数与绘制的高亮可能不一致；计数拥有导航权，绘制只负责可见部分。
- DOM 揭示是对 disclosure 头部的尽力遍历，以其他方式隐藏行的自定义渲染器只是不滚动。

## 备选方案

- **基于 DOM 的搜索（`window.find` 或扫描渲染文本）**：无法计数或导航到收起的行，并与虚拟化对抗而非利用投影。
- **在消息渲染器中包裹 `<mark>`**：改动渲染内容，破坏选区语义，并把匹配逻辑分散到每个渲染器。
- **把查找状态存入 Chat store**：该 store 是 Session 拥有的会话状态；查找状态是视图局部的临时状态，因此与打开标志一起放在 apply 闭包中。
